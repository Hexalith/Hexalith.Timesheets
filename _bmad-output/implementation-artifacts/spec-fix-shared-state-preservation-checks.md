## Intent

**Problem:** The isolated live fixture reported a shared-state mismatch without identifying which service changed. The retained evidence proves real writes (14 added persistent Redis DB0 keys and changed scheduler KV), but cannot identify their writer. Admission also ignores standalone Dapr applications with unrelated IDs and takes no pre-resource stability observation.

**Approach:** Keep preservation fail-closed and make its report identify Redis persistent-content, TTL-content/deadline, and scheduler identity/content changes without disclosing keys or values. Reject all running Dapr applications before fixture startup, using the CLI's structured inventory. Compare two read-only shared snapshots before creating infrastructure and refuse a changing baseline, preserving both snapshots and the comparison. Apply the same baseline admission and final mismatch diagnostics to the compiled guard driver. Preserve natural-expiry allowances, original command failures, owned-resource cleanup, privacy filtering, all real journey assertions, and ordinary AppHost behavior. Do not clear, restore, migrate, or otherwise mutate shared state, stop unrelated runtimes, or attribute historical writes to an unproven source. EventStore restart repair and deployed qualification remain outside this increment.

## Review Triage Log

- BH1 — medium, patch: equal final scheduler range bytes do not establish an inactive baseline when its revision advances. Baseline-only revision equality now refuses that activity; the existing final-state comparison still permits revision-only changes when identity/range match. Added a regression distinguishing these contracts. The revision behavior is documented by the [etcd API](https://etcd.io/docs/v3.5/learning/api/#revisions).
- BH2 — medium, patch: empty CLI JSON can omit a running sidecar when process inspection fails. Installed Dapr CLI 1.18.2 has skip paths for unavailable command-line/creation-time metadata in its [list implementation](https://github.com/dapr/cli/blob/v1.18.2/pkg/standalone/list.go). A visible-process cross-check now refuses live sidecars or unavailable inspection without reading their arguments or signaling them; fake proc files and a real harmless named subprocess verify it.
- BH3 — medium, patch: a foreign runtime appearing during baseline sampling was detected only after infrastructure creation. Both drivers now repeat admission immediately after sampling; new live/guard regressions verify zero private-infrastructure creation and zero foreign stop in that window.
- BH4 — low, patch: baseline evidence lacked sample timing. The comparison now records wall-clock sample times, monotonic elapsed seconds, and requested pause; the stable-baseline regression checks these fields and the one-second sleep call.
- BH5 — medium, patch: final-mutation behavior was tested only through the live driver. The guard regression now verifies service-specific diagnostics, failure status after success or an existing probe failure, and owned cleanup. All findings received bounded fixes; no review deferrals were added.
